## 1. Executive Summary

This roadmap defines the prioritized engineering steps required to remediate the architectural violations discovered during the Global Semantic Architecture Audit.

To maintain architectural integrity and prevent scope inflation:
- **No new milestones are created.**
- Remediations are assigned directly to their original owning stages (Stages 1–4) and foundational milestones (B1–B4).
- The remediation plan is divided into four priority tiers:
  - **P0 — Critical (Blocks Step 1 V2.2):** Violations that directly intercept, bypass, or corrupt semantic execution in production.
  - **P1 — Major (Post-Step 1 Core Hardening):** Violations that distort domain adaptability or linguistic resilience.
  - **P2 — Moderate (Architectural Parameterization):** Static thresholds and feature weights that should be configurable or learned.
  - **P3 — Cleanup (Technical Debt):** Dead code and deprecated legacy modules.

## 2. P0: Critical Remediations (BLOCKS Step 1 V2.2)

These five remediations must be approved and scheduled before implementing Step 1 V2.2 to prevent mutation integration from perpetuating brittle regex and heuristic execution paths.

### `REM-P0-01`: Deprecate Front-Door Regex Interception in Supervisor
- **Affected Stage / Milestone:** Stage 1 (Conversation Orchestration) / Stage 4 (Dynamic Dispatch)
- **Files Involved:**
  - `packages/execution-kernel/src/orchestration/supervisor/Supervisor.ts` (lines 148–199)
  - `packages/execution-kernel/src/orchestration/supervisor/FastPathExecutor.ts` (lines 32–90, 95–215)
- **Root Cause:** `FastPathExecutor` was introduced as a premature latency optimization, intercepting high-velocity commands with regex capture groups before semantic understanding, short-term memory, or entity resolution can run.
- **Required Architectural Change:**
  - Remove line 149 from `Supervisor.ts` (`if (this.fastPath.canHandle(...))`).
  - Route all utterances through `SemanticIntentInterpreter`.
  - Introduce a semantic fast-execution gate: if `SemanticIntentInterpreter` returns a single, unambiguous atomic mutation operation with confidence $> 0.95$, dispatch it directly to `KernelCapabilityService` without spawning multi-agent ReAct loops.
- **Dependencies:** None.
- **Regression Risks:** High-velocity commands (`"mark task 123 done"`) may see latency increase from ~150ms to ~600ms (Groq inference).
- **Verification Requirements:** Verify with conversational benchmark test suite; verify full entity resolution and priority preservation on all task mutations.
- **Blocks Step 1 V2.2:** **YES.**

### `REM-P0-02`: Connect LLM Client to DynamicWorkflowPlanner in Supervisor
- **Affected Stage / Milestone:** Stage 4 (Dynamic Workflow Orchestration)
- **Files Involved:**
  - `packages/execution-kernel/src/orchestration/supervisor/Supervisor.ts` (line 297)
  - `packages/execution-kernel/src/orchestration/planning/DynamicWorkflowPlanner.ts` (lines 224–312)
- **Root Cause:** `Supervisor.ts` instantiates `new DynamicWorkflowPlanner()` with no arguments, causing `this.llmClient` to be `undefined` and forcing the planner into hardcoded benchmark JSON fallbacks.
- **Required Architectural Change:**
  - Pass the active LLM client wrapper into `DynamicWorkflowPlanner` at line 297 of `Supervisor.ts`.
  - Enable model-based DAG generation grounded in `CapabilityRegistry.getInstance().getDiscoveredCapabilities()`.
  - Remove `generateDeterministicFallback` from production execution paths, restricting it strictly to test fixtures.
- **Dependencies:** `CapabilityRegistry`.
- **Regression Risks:** Invalid DAGs generated by LLM if prompts lack topological constraints. `PlanValidator` must strictly enforce Kahn's cycle checks.
- **Verification Requirements:** Test with novel multi-step user requests (e.g. *"Read my recent Notion notes and export a summary to local storage"*).
- **Blocks Step 1 V2.2:** **YES.**

---

### `REM-P0-03`: Replace 22-Line String Whitelist with CapabilityRegistry Contract Lookup
- **Affected Stage / Milestone:** Stage 1 (Supervisor) / Stage 4 (Capabilities) / B4 (HITL Governance)
- **Files Involved:**
  - `packages/execution-kernel/src/orchestration/supervisor/Supervisor.ts` (lines 929–955)
  - `packages/execution-kernel/src/orchestration/capabilities/CapabilityRegistry.ts`
- **Root Cause:** Supervisor uses a 22-line list of `.includes(...)` strings to guess whether an operation is read-only or requires human confirmation.
- **Required Architectural Change:**
  - Query `CapabilityRegistry.getInstance().getCapability(capURN)`.
  - Read authoritative descriptor properties: `descriptor.requiresApproval`, `descriptor.isReadOnly`, and `descriptor.riskClass`.
  - Eliminate the hardcoded string whitelist entirely.
- **Dependencies:** `CapabilityRegistry`.
- **Regression Risks:** External tools or MCP capabilities registered without explicit `requiresApproval` metadata may trigger default security policies.
- **Verification Requirements:** Verify that new MCP tools declaring `requiresApproval: false` execute without HITL prompts, while high-risk mutations prompt for confirmation.
- **Blocks Step 1 V2.2:** **YES.**

---

### `REM-P0-04`: Eliminate Assistant Prose Keyword Inspection for Action Coercion
- **Affected Stage / Milestone:** Stage 1 (Conversational Supervisor)
- **Files Involved:**
  - `packages/execution-kernel/src/orchestration/supervisor/Supervisor.ts` (lines 473–478)
- **Root Cause:** Supervisor inspects generated LLM prose for keywords (`"class"`, `"schedule"`, `"block"`, `"routine"`) to coerce the underlying action type to `"create_temporal_series"`.
- **Required Architectural Change:**
  - The pending operation's action type must be determined exclusively by `semanticTurn.operations[0].actionType` or structured clarification metadata.
  - Remove all substring checks on assistant prose.
- **Dependencies:** `SemanticIntentInterpreter`.
- **Regression Risks:** Conversational turns where the model omitted structured action types will need explicit clarification turns rather than heuristic guessing.
- **Verification Requirements:** Verify that tasks containing the word "block" (e.g. *"Block spam emails"*) remain tasks and are not coerced into temporal series.
- **Blocks Step 1 V2.2:** **YES.**

---

### `REM-P0-05`: Eliminate Dynamic Timestamps from Idempotency Keys
- **Affected Stage / Milestone:** Stage 1 / Milestone B2 (Unified Causal Integration)
- **Files Involved:**
  - `packages/execution-kernel/src/orchestration/supervisor/FastPathExecutor.ts` (lines 121, 138, 159, 174, 189)
- **Root Cause:** Fast-Path appends `${Date.now()}` to idempotency keys, guaranteeing that duplicate retries receive different keys.
- **Required Architectural Change:**
  - Derive idempotency keys deterministically from the client request ID, turn ID, and operation index (e.g. `idem_${requestId}_${turnId}_${opIndex}`).
- **Dependencies:** Client request metadata.
- **Regression Risks:** None. Restores required distributed systems idempotency.
- **Verification Requirements:** Execute immediate retry of the same payload; verify kernel returns `REJECTED_IDEMPOTENT_DUPLICATE`.
- **Blocks Step 1 V2.2:** **YES.**
